# Migration 0.3.0

Nothing in your notes or wiki pages has to change for this release, and no existing setting changes its
meaning. Everything new — the control center (settings, suggestions, analysis, MCP area, live glow), the
importer for old brains and the background harvest — arrives with the regular system-file update (step
"replace `.tools`" in the **update** skill). Every new automation that uses AI is **off** by default; with
all switches off, the brain behaves like 0.2.

Settings made in the control center are stored in a new section `automatik` of `brain.config.json`. It is
created the first time someone saves a setting — nothing to add by hand. The existing keys (`hinweis`,
`update.auto`, `backup`) keep working.

This migration does four things: it checks the downloaded kit, generates `AGENTS.md` again (so every agent
learns the new sentences "import my old brain" and "how good is my brain"), adds the template for the
"me" card `ich.md` if it is missing, and re-runs the Claude Code adapter if it is installed (it registers
the new hooks for the live glow and the harvest).

**Placeholders:** put in `<vault>` and `<kit-klon>` as **absolute paths, no `~`** (for example
`/Users/<name>/.brain-kit/kit/v0.3.0` or `C:\Users\<name>\.brain-kit\kit\v0.3.0`), always inside the double
quotes shown below. Every path is passed to Node as an argument, never written into the JavaScript itself.

## What's new for the person

- "show me my brain" / „zeig mir mein Brain" now starts a small local service (only `127.0.0.1`, protected by
  a random key that changes on every start) and opens the brain with the **control center**: a gear for
  the settings, new **suggestions** to accept or discard with one click, an **analysis** tab and the
  **MCP tools** as their own region. If the service can't start, the view opens read-only as before.
- "import my old brain from <folder>" / „importiere mein altes Brain aus <Ordner>" → skill **import**
  (`node "<vault>/.tools/brain.mjs" import <folder|zip>`). Copies into `<inbox>/_import/<name>/` and reports
  duplicates and contradictions before anything enters the wiki.
- "how good is my brain" / „wie gut ist mein Brain" → `node "<vault>/.tools/brain.mjs" analyse`.
- Settings also work in the terminal: `node "<vault>/.tools/brain.mjs" einstellungen [key=value …]`.
- New optional page `<wiki>/ich.md` (the "me" card). It is only read when the switch "me card" is on.

## Step 1 — Check the release brings the control center

**Do:** nothing — this step only confirms the downloaded kit is complete before `.tools` is replaced.

**Check:**
```
node -e "const fs = require('node:fs'), p = require('node:path'), k = process.argv[1]; process.exit(['.tools/ansicht/dienst.mjs', '.tools/ansicht/steuer.js', '.tools/import/import.mjs', 'vorlage/wiki/ich.md'].every(f => fs.existsSync(p.join(k, f))) ? 0 : 1)" "<kit-klon>"
```
**Expected:** exit code `0`.

## Step 2 — Generate AGENTS.md (and the Codex skills) from the new release

**Do:**
```
node "<kit-klon>/.tools/skills-build.mjs" "<vault>" --ziel agents "<vault>/AGENTS.md"
```
Only if the folder `<vault>/.agents/skills` exists (the installer creates it for Codex) — also:
```
node "<kit-klon>/.tools/skills-build.mjs" "<vault>" --ziel agents-skills "<vault>/.agents/skills"
```

**Check:**
```
node -e "process.exit(/brain\.mjs\W+analyse/.test(require('node:fs').readFileSync(process.argv[1], 'utf8')) ? 0 : 1)" "<vault>/AGENTS.md"
```
**Expected:** exit code `0` (the new AGENTS.md knows `brain.mjs" analyse`).

## Step 3 — Add the "me" card template (only if it is missing)

The wiki folder comes from `brain.config.json` (`ordner.wiki`, otherwise `wiki.ordner`, otherwise `09_wiki`).
An existing `ich.md` is **never** overwritten.

**Do:**
```
node -e "const fs = require('node:fs'), p = require('node:path'), [v, k] = process.argv.slice(1); let c = {}; try { c = JSON.parse(fs.readFileSync(p.join(v, 'brain.config.json'), 'utf8').replace(/^\uFEFF/, '')); } catch {} const w = p.join(v, (c.ordner && c.ordner.wiki) || (c.wiki && c.wiki.ordner) || '09_wiki', 'ich.md'); if (!fs.existsSync(w)) { fs.mkdirSync(p.dirname(w), { recursive: true }); fs.copyFileSync(p.join(k, 'vorlage', 'wiki', 'ich.md'), w, fs.constants.COPYFILE_EXCL); }" "<vault>" "<kit-klon>"
```

**Check:**
```
node -e "const fs = require('node:fs'), p = require('node:path'), v = process.argv[1]; let c = {}; try { c = JSON.parse(fs.readFileSync(p.join(v, 'brain.config.json'), 'utf8').replace(/^\uFEFF/, '')); } catch {} process.exit(fs.existsSync(p.join(v, (c.ordner && c.ordner.wiki) || (c.wiki && c.wiki.ordner) || '09_wiki', 'ich.md')) ? 0 : 1)" "<vault>"
```
**Expected:** exit code `0`.

## Step 4 — Register the new Claude Code hooks (only if Claude Code is connected)

The adapter adds a hook that notes which page or MCP tool was used (for the live glow and the analysis —
it never writes anything into the conversation) and the triggers for the background harvest (they do
nothing while the harvest switches are off). Skip this step — including its check — if the first check
below exits with `1` (no Claude Code adapter installed, e.g. with Codex, Gemini or Cursor).

**Check whether the adapter is installed:**
```
node -e "const f = require('node:path').join(require('node:os').homedir(), '.claude', 'commands', 'brain-update.md'); const fs = require('node:fs'); process.exit(fs.existsSync(f) && fs.readFileSync(f, 'utf8').includes('brain-kit -->') ? 0 : 1)"
```
**Exit code `0`** → **Do:** run the adapter from the new release (idempotent; it merges its hooks into
`~/.claude/settings.json` with a backup and never touches other hooks or your own commands):
```
node "<kit-klon>/.tools/adapters/claude-code/install.mjs" "<vault>"
```

**Check:**
```
node -e "const f = require('node:path').join(require('node:os').homedir(), '.claude', 'settings.json'); process.exit(require('node:fs').readFileSync(f, 'utf8').includes('werkzeug-protokoll.mjs') ? 0 : 1)"
```
**Expected:** exit code `0` (`settings.json` now carries the `werkzeug-protokoll.mjs` hook).

## Done

Set `systemVersion` to `0.3.0` in `brain.config.json` and commit (the **update** skill does this). After
`.tools` has been replaced, one run confirms the new settings are readable:
```
node "<vault>/.tools/brain.mjs" einstellungen
```
**Expected:** one line per setting, among them `liveAufleuchten=true`, and exit code `0`.
