# Migration 0.4.0

Nothing in your notes or wiki pages has to change for this release, and no existing setting changes its
meaning — **this migration does not touch your notes or wiki pages** (only, if needed, the explanation in
`_schema.md`, step 4). Everything new — expiry dates for stale knowledge,
resolving conflicts in the brain, the weekly maintenance report, the opt-in maintenance run, the local
benchmark, the MCP logos and the lesson suggestions — arrives with the regular system-file update (step
"replace `.tools`" in the **update** skill). Every new automation that uses AI stays **opt-in**. Two local,
0-token features are **on by default**: the weekly line at session start (`wochenbericht`) and local lesson
suggestions (`lektionen: lokal`, short excerpts of repeated corrections land as suggestions in
`<inbox>/_vorschlaege/`) — switch them off in the control centre if you want the 0.3 behaviour.

The optional frontmatter fields `stand` and `pruefen_bis`, and the new `automatik` settings
(`wochenbericht`, `pflegeLauf`, `lektionen`), need nothing added by hand — pages without the new fields are
treated exactly as before (neither expired nor checked), and the settings get their defaults the first time
someone saves any setting.

This migration does four things: it checks the downloaded kit, generates `AGENTS.md` again (so every agent
learns the new sentence "what needs doing in the brain"), re-runs the Claude Code adapter if it is
installed (new hook triggers for the maintenance run and the lesson suggestions do nothing while their
switches are off, but need registering once), and adds the explanation of `stand`/`pruefen_bis` to the
vault's wiki schema if it is missing there (the schema is only copied at install time).

**Placeholders:** put in `<vault>` and `<kit-klon>` as **absolute paths, no `~`** (for example
`/Users/<name>/.brain-kit/kit/v0.4.0` or `C:\Users\<name>\.brain-kit\kit\v0.4.0`), always inside the double
quotes shown below. Every path is passed to Node as an argument, never written into the JavaScript itself.

## What's new for the person

- Pages with a fast-changing fact (a price, a version, a status) can carry `stand: YYYY-MM-DD` and
  `pruefen_bis: YYYY-MM-DD` — once the date passes, `brain-lint` and the 3D brain mark the page `ABGELAUFEN`
  (amber ring). The existing `verfall: <days>` field still works; both get the stricter of the two dates.
- Contradictions can now be resolved with one click, right in the brain's **Pflege** tab: "A is right" /
  "B is right" / "both apply" / "later" writes a decision order; your AI carries it out on the next ingest
  (never the brain itself — the wiki is never written from the click).
- "what needs doing in the brain" / „was ist im Brain zu tun" → `node "<vault>/.tools/brain.mjs" pflege`:
  expired pages, open conflicts and decisions, duplicates, orphans, in one short report with a next step in
  plain language each. Once a week, the session start names it in one line, only if something is open.
- "how good is my brain" also runs a local search benchmark now: `node "<vault>/.tools/brain.mjs" messlatte`.
- New settings (unless noted, off/default like before): `wochenbericht` (the weekly line, **on** by
  default), `pflegeLauf` (a weekly or on-click AI maintenance pass that only ever writes suggestions, never
  the wiki), `lektionen` (local-only by default — turns repeated corrections or repeated tool failures in a
  Claude Code session into a lesson suggestion for Memory or a skill; `mit-ki` adds Haiku to word it).
- MCP servers in the brain's "brain stem" now show the real logo of well-known services (Simple Icons,
  CC0) instead of an anonymous dot, grouped by where they're configured.

## Step 1 — Check the release brings self-maintenance

**Do:** nothing — this step only confirms the downloaded kit is complete before `.tools` is replaced.

**Check:**
```
node -e "const fs = require('node:fs'), p = require('node:path'), k = process.argv[1]; process.exit(['.tools/pflege.mjs', '.tools/gueltigkeit.mjs', '.tools/konflikte.mjs', '.tools/ansicht/vendor/icons/zuordnung.json'].every(f => fs.existsSync(p.join(k, f))) ? 0 : 1)" "<kit-klon>"
```
**Expected:** exit code `0`.

## Step 2 — Generate AGENTS.md again

**Do:**
```
node "<kit-klon>/.tools/skills-build.mjs" "<vault>" --ziel agents "<vault>/AGENTS.md"
```
Only if the folder `<vault>/.agents/skills` exists (the installer creates it for Codex) — also:
```
node "<kit-klon>/.tools/skills-build.mjs" "<vault>" --ziel agents-skills "<vault>/.agents/skills"
```

**Check:**
```
node -e "process.exit(/brain\.mjs\W+pflege/.test(require('node:fs').readFileSync(process.argv[1], 'utf8')) ? 0 : 1)" "<vault>/AGENTS.md"
```
**Expected:** exit code `0` (the new AGENTS.md knows `brain.mjs" pflege`).

## Step 3 — Register the new Claude Code hooks (only if Claude Code is connected)

The adapter is idempotent and safe to re-run even where nothing changed for a given vault; doing it now
means the maintenance-run and lesson-suggestion triggers are registered before anyone turns their switches
on. Skip this step — including its check — if the first check below exits with `1` (no Claude Code adapter
installed, e.g. with Codex, Gemini or Cursor).

**Check whether the adapter is installed:**
```
node -e "const f = require('node:path').join(require('node:os').homedir(), '.claude', 'commands', 'brain-update.md'); const fs = require('node:fs'); process.exit(fs.existsSync(f) && fs.readFileSync(f, 'utf8').includes('brain-kit -->') ? 0 : 1)"
```
**Exit code `0`** → **Do:** run the adapter from the new release (merges its hooks into
`~/.claude/settings.json` with a backup and never touches other hooks or your own commands):
```
node "<kit-klon>/.tools/adapters/claude-code/install.mjs" "<vault>"
```

**Check:**
```
node -e "const f = require('node:path').join(require('node:os').homedir(), '.claude', 'settings.json'); const s = require('node:fs').readFileSync(f, 'utf8'); process.exit(s.includes('ernte-ausloeser.mjs') && s.includes('session-start.mjs') ? 0 : 1)"
```
**Expected:** exit code `0` (`settings.json` still carries exactly one entry for each hook — re-running
never duplicates them).

## Step 4 — Explain the new fields in the wiki schema (only if missing)

`_schema.md` in the wiki folder was copied once at install time, so existing vaults don't explain `stand` and
`pruefen_bis` yet. This step appends the paragraph from the new template — only if the schema exists and does
not mention `pruefen_bis` yet (running it twice changes nothing).

**Do:**
```
node -e "const fs = require('node:fs'), p = require('node:path'), [v, k] = process.argv.slice(1); let c = {}; try { c = JSON.parse(fs.readFileSync(p.join(v, 'brain.config.json'), 'utf8')); } catch {} const ziel = p.join(v, (c.ordner && c.ordner.wiki) || (c.wiki && c.wiki.ordner) || '09_wiki', '_schema.md'); if (!fs.existsSync(ziel)) process.exit(0); const s = fs.readFileSync(ziel, 'utf8'); if (s.includes('pruefen_bis')) process.exit(0); const m = fs.readFileSync(p.join(k, 'vorlage', 'wiki', '_schema.md'), 'utf8').replace(/\r\n/g, '\n').match(/^- Gültigkeit:[\s\S]*?(?=\n- |\n\n|\n##)/m); if (!m) process.exit(1); fs.writeFileSync(ziel, s.trimEnd() + '\n\n## Gültigkeit (seit 0.4.0)\n' + m[0] + '\n');" "<vault>" "<kit-klon>"
```

**Check:**
```
node -e "const fs = require('node:fs'), p = require('node:path'), v = process.argv[1]; let c = {}; try { c = JSON.parse(fs.readFileSync(p.join(v, 'brain.config.json'), 'utf8')); } catch {} const ziel = p.join(v, (c.ordner && c.ordner.wiki) || (c.wiki && c.wiki.ordner) || '09_wiki', '_schema.md'); process.exit(!fs.existsSync(ziel) || fs.readFileSync(ziel, 'utf8').includes('pruefen_bis') ? 0 : 1)" "<vault>"
```
**Expected:** exit code `0` (either the schema now explains `pruefen_bis`, or there is no schema to update).

## Done

Set `systemVersion` to `0.4.0` in `brain.config.json` and commit (the **update** skill does this). After
`.tools` has been replaced, one run confirms the maintenance report is readable:
```
node "<vault>/.tools/brain.mjs" pflege
```
**Expected:** exit code `0`, starting with a line `Pflegebericht (<date>): …` (for example "nichts zu tun" if
the vault is already in good shape, otherwise one plain-language line per thing found).
