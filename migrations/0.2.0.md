# Migration 0.2.0

Nothing in your notes, wiki pages or `brain.config.json` has to change for this release. The new 3D brain
view (`.tools/ansicht/`) arrives with the regular system-file update (step "replace `.tools`" in the
**update** skill), like every other tool. The vault's `AGENTS.md` (and, with Codex, `.agents/skills/`) is
generated again from the new release in Step 2 — without that, agents other than Claude Code would never
learn the new sentence "show me my brain". Step 3 renews the Claude Code commands, which hold a copy of each skill.

**Placeholders:** put in `<vault>` and `<kit-klon>` as **absolute paths, no `~`** (for example
`/Users/<name>/.brain-kit/kit/v0.2.0` or `C:\Users\<name>\.brain-kit\kit\v0.2.0`), always inside the double
quotes shown below. Every path is passed to Node as an argument, never written into the JavaScript itself.

## What's new for the person

- "show me my brain" / „zeig mir mein Brain" → `node "<vault>/.tools/brain.mjs" zeig` builds the data
  (`<vault>/.logs/ansicht/data.js`) and opens `<vault>/.tools/ansicht/index.html` in the browser.
  `--nur-daten` only builds the data, `--nicht-oeffnen` prints the file path instead of opening it.
- Areas in the view come from `clusters` in `brain.config.json`; optionally `ansicht.regionen`
  (`{ "<clusterId>": "frontal|temporal|parietal|tief|okzipital" }`) pins an area to a brain region.
  Nothing to set — the defaults work.
- `.logs/` is already in the vault's `.gitignore`, so the generated data is never committed or backed up.

## Step 1 — Check the release brings the view

**Do:** nothing — this step only confirms the downloaded kit is complete before `.tools` is replaced.

**Check:**
```
node -e "process.exit(require('node:fs').existsSync(process.argv[1]) ? 0 : 1)" "<kit-klon>/.tools/ansicht/index.html"
```
**Expected:** exit code `0`.

## Step 2 — Generate AGENTS.md (and the Codex skills) from the new release

`AGENTS.md` is never committed and only rewritten by the installer and by the Claude Code session start.
With Codex, Gemini, Cursor or any other agent it would otherwise stay on the 0.1.0 text. This step renders it
from `<kit-klon>` directly, so it works whether or not `.tools` has already been replaced.

**Do:**
```
node "<kit-klon>/.tools/skills-build.mjs" "<vault>" --ziel agents "<vault>/AGENTS.md"
```
Only if the folder `<vault>/.agents/skills` exists (the installer creates it for Codex) — also:
```
node "<kit-klon>/.tools/skills-build.mjs" "<vault>" --ziel agents-skills "<vault>/.agents/skills"
```

**Check:**
```
node -e "process.exit(/brain\.mjs\W+zeig/.test(require('node:fs').readFileSync(process.argv[1], 'utf8')) ? 0 : 1)" "<vault>/AGENTS.md"
```
**Expected:** exit code `0` (the new AGENTS.md knows `brain.mjs" zeig`).

## Step 3 — Renew the Claude Code commands (only if Claude Code is connected)

The Claude Code adapter copies the full text of every skill into `~/.claude/commands/` (`brain-update.md`,
`ingest.md`, …). Nothing else rewrites them — without this step, Claude Code would run the 0.1.0 update skill
forever. Skip this step if the first check below exits with `1` (no Claude Code adapter installed).

**Check whether the adapter is installed:**
```
node -e "const f = require('node:path').join(require('node:os').homedir(), '.claude', 'commands', 'brain-update.md'); const fs = require('node:fs'); process.exit(fs.existsSync(f) && fs.readFileSync(f, 'utf8').includes('brain-kit -->') ? 0 : 1)"
```
**Exit code `0`** → **Do:** run the adapter from the new release (idempotent; it merges its hooks into
`~/.claude/settings.json` with a backup and never touches other hooks or your own commands):
```
node "<kit-klon>/.tools/adapters/claude-code/install.mjs" "<vault>"
```

**Check:**
```
node -e "const f = require('node:path').join(require('node:os').homedir(), '.claude', 'commands', 'brain-update.md'); process.exit(require('node:fs').readFileSync(f, 'utf8').includes('skills-build.mjs') ? 0 : 1)"
```
**Expected:** exit code `0` (`brain-update.md` now carries the new update skill, which regenerates `AGENTS.md`).

## Done

Set `systemVersion` to `0.2.0` in `brain.config.json` and commit (the **update** skill does this). After
`.tools` has been replaced, one run confirms the view works without opening a browser:
```
node "<vault>/.tools/brain.mjs" zeig --nur-daten
```
**Expected:** a line like `42 Seiten, 57 Verbindungen.` and exit code `0`.
